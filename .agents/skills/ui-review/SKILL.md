# UI review

1. Read `docs/design-system.md`, `AGENTS.md` and the target page/component.
2. Review layout, typography, spacing, colours, imagery and interaction states against the existing site.
3. Check desktop, tablet and mobile widths **if browser/screenshot tools are available**. Do not claim visual verification without actually inspecting rendered output.
4. Check semantic heading order, image alternatives, form labels, focus states, contrast and mobile overflow.
5. Check British English, link destinations and credibility of experience claims.
6. Present findings in priority order with file locations. Do not change code unless asked.
